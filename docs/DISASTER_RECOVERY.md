# Disaster Recovery Plan (Version 1.0)

This document outlines the backup, restoration, and incident response procedures for DocsMind infrastructure.

## 1. Recovery Objectives
- **Recovery Point Objective (RPO)**: 1 Hour (Maximum acceptable data loss).
- **Recovery Time Objective (RTO)**: 4 Hours (Maximum acceptable downtime during a major failure).

## 2. PostgreSQL (Primary Datastore)
- **Backup**: Managed Cloud SQL/RDS automated backups enabled (7-day retention). WAL (Write-Ahead Logging) archiving enabled for Point-in-Time Recovery (PITR).
- **Restore**:
  1. Spin up a new RDS instance using the snapshot from the latest healthy state.
  2. Update the `DATABASE_URL` secret in AWS Secrets Manager / Azure Key Vault.
  3. Force a rolling restart of the backend/worker ECS containers to pick up the new connection string.

## 3. Qdrant (Vector Database)
- **Backup**: Qdrant Cloud handles automated daily snapshots. If self-hosted, use the Qdrant Snapshot API via a cron job (Celery Beat) uploading to S3.
- **Restore**:
  1. Retrieve the latest `.snapshot` file from S3.
  2. Use the Qdrant Restore API endpoint `POST /collections/{collection_name}/snapshots/recover`.
  3. Note: If vector data is permanently lost, it can be regenerated by wiping the collection and dispatching a batch Celery job to re-embed all documents stored in Postgres.

## 4. Redis (Cache, Celery Broker, JWT Denylist)
- **Backup**: ElastiCache automated daily backups (RDB snapshots).
- **Restore**:
  - Redis data is largely ephemeral (background task queues and rate limiting).
  - **Exception**: The JWT Denylist (Refresh Token Rotation). If Redis is lost, recently revoked refresh tokens could theoretically be replayed.
  - **Mitigation**: Upon Redis restoration, all active sessions can be bulk-invalidated by rotating the backend `SECRET_KEY`, forcing all users to re-authenticate immediately.

## 5. High Availability (HA) Failover
- The Frontend, Backend, and Celery Workers are completely stateless.
- If an Availability Zone (AZ) goes down, the orchestrator (ECS/K8s) will automatically provision replacement containers in a healthy AZ. No manual intervention is required.
